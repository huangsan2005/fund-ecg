# 预测台账（Prediction Ledger）

> 机制说明：所有公开预测登记可证伪判据与对表日期，预测后管理者的**应对动作**（降价/砍研发/冻结招聘/定增/卖资产）作为最高权重校准信号回写引擎。管理者可以讲错故事，但不会把钱花在错误的变量上——每个应对动作都是其内部模型的一次泄露。规则：预测必须带可证伪判据；对表后判定三档（方向对/恶化快于预期/塌了）；应对动作回写 product-decisions.md 阈值。

## 登记格式

| 字段 | 说明 |
|---|---|
| ID | P-序号 |
| 预测日 | 登记日期 |
| 内容 | 可证伪形式的预测 |
| 判据 | 具体数字/事件，对表时逐项核对 |
| 对表时点 | 定期报告或事件日 |
| 状态 | 待验证/方向对/恶化快于预期/塌了/已修正 |
| 应对回写 | 管理层实际动作对引擎参数的修正 |

## 对表纪律

1. 每季固定动作：新披露数据 vs 判据逐项核对，判定三档，台账更新
2. 管理层应对动作优先级最高：企业的真金白银动作与我们的预测冲突时，**先怀疑预测再怀疑动机**
3. 塌了的预测不删除——记录错误原因（数据缺失/机制误判/黑天鹅），错误分类统计回写ABCD分级闸门
4. 预测全部公开于GitHub仓库（脱敏后），兑现与证伪同权记录——产品的公信力来自敢登记敢对表
